# Atlas environnemental

Page: `/atlas`. The existing `/carte` remains the inventory interface and does not advertise the atlas yet. Layer controls, opacity, attribution, dates, retry and recentering are available. Browser-side external requests run only for enabled layers; bathing-water results, the river station catalogue and river assessments are fetched at build/render time alongside the inventory. Detailed Hub’Eau analyses run on clicking a water point/network; drinking-water summaries load on layer activation (one row per unique distribution network, four requests concurrently at most). All requests are bounded and cancellable.

## Current atlas perimeter (10 September 2026)

Every data layer is restricted to the polygon union of the ten CCPMB communes using `ccpmb-territory.ts` and the pinned official commune contours: inventory, Atmo (hourly/daily and seeded stations), rivers (build snapshot and browser refresh), drinking-water commune markers, bathing sites, biosurveillance demos, soil demos, roads and residential heating. Point filtering precedes displayed counts and downstream detail requests. The heatmap uses per-row polygon intersections, including holes and shared borders, to make all out-of-territory pixels transparent. Initial view and recentering use the territory bounds; the background map remains available as geographic context.

The inventory filter is an immutable atlas-only view (`atlas-inventory.ts`); `/carte` and its shared source are unchanged. The six-site bathing registry is preserved, but only Passy Îles, Passy Cavettaz and Sallanches Ilettes are fetched and shown. Servoz, Thyez, Morillon, Samoëns and the Chamonix valley are outside the atlas data scope. Unmapped inventory records remain accessible in the separate inventory, not assigned invented map locations.

Verified export: 59 inventory sites and 29 river stations; live commune catalogue: exactly the ten CCPMB communes. Roads retain 27 sections (20 counted); bathing retains three sites. Browser regression `scripts/check-atlas-territory.mjs` checks desktop/mobile export points, cached river outage/recovery, outside-point rejection for live water/air, sidebar counts, demo layers and heatmap pixels. Unit coverage includes source immutability, scanline holes/unions and every coloured pixel of a test raster. Production build, 62 tests, desktop/mobile territory, road and bathing checks pass. Earlier verification counts below refer to the previous broader perimeter.

## Fictional wood-heating demonstration

“Chauffage résidentiel” is an opt-in, entirely synthetic heatmap, separate from all provider data. Its 19 fixed illustrative hotspots are blended into a blue/cyan/green/yellow/red raster in Web Mercator coordinates so it stays geographically aligned during zoom and pan. The Chamonix valley hotspots (Bossons, centre, Les Praz and Argentière) and Les Houches (including Vaudagne) are excluded; Les Contamines-Montjoie and Praz-sur-Arly have village-centred illustrative areas. The legend is unitless and the sidebar explicitly labels the data as fictional; there is no floating notice over the map. It represents neither measurements, household locations, emissions estimates nor health thresholds. It makes no API requests and renders below the other layers with adjustable opacity. Regression check: `node --experimental-strip-types --test scripts/wood-heatmap.test.mjs`.

## Connected sources (checked 8 September 2026)

Atlas details now open in a shared native `dialog` (`AtlasDetailDialog`) outside the Leaflet map. The browser top layer prevents map/header clipping and makes the background inert. The report-style layout takes visual inspiration from the supplied Lac de Passy HTML (overview facts and parameter rows), using the site's blue-and-white palette for the header, cards, charts and links; semantic data-quality colours stay unchanged. No sample data, thresholds or health assertions from that reference are imported. Desktop width is capped at 1,040 px; mobile uses the full viewport. A fixed header/close control and footer surround one vertical content scroller. Escape, backdrop click and the return button close it; body scrolling is locked and keyboard focus returns to the originating marker. `AtlasMarker` preserves Enter/Space activation without Leaflet Popup. Air keeps all pollutants visible in responsive cards, charts and expandable tables. Water groups the latest ten results by parameter without discarding dates, units, network scope or qualifiers. Inventory pins display complete site fields in the same overlay, leaving `/carte` unchanged. Run `scripts/check-atlas-popups.mjs` (legacy command name) with Playwright on NODE_PATH and Chrome installed; isolated fixtures cover inventory, async water, all pollutants, mobile, resizing, focus and closing behaviour.

- **Inventory**: same `fetchAllPollutionSites()` and sector pin icons as `/carte`. Sources without coordinates link back to the inventory, rather than receiving invented locations. This project uses static export: the initial inventory is refreshed by a rebuild, not by Next.js ISR on the deployed static files.
- **Hub’Eau rivers / Naïades + AERMC**: `/api/v2/qualite_rivieres/station_pc?code_departement=74&size=1000` supplies station coordinates. Join official AERMC assessments by exact eight-digit station ID (see colours below). Clicking a station requests up to 10 recent `analyse_pc` rows. Preserve parameter name, result, units, sampling date and `mnemo_remarque` (including detection/quantification qualifiers).
- **ARS / Ministry of Health drinking-water controls via Hub’Eau**: `communes_udi?code_commune=…` supplies network coverage; `resultats_dis?code_reseau=…&size=10&sort=desc` supplies the selected network's analyses. Do not use the `resultats_dis` commune filter to infer serving networks: it refers to the sampling commune. Communes are positioned using the official [API Découpage administratif](https://geo.api.gouv.fr/communes?codeDepartement=74&fields=nom,code,centre&format=json). These are navigation markers, NOT sample points or catchments. Their colour summarizes dated network sample assessments with explicit coverage, never guarantees current commune-wide potability. The [Health Ministry confirms Hub’Eau's reuse of its sanitary-control dataset](https://sante.gouv.fr/sante-et-environnement/eaux/eau).

Coverage is bounded to 6.45–7.10° E, 45.70–46.10° N; water/commune catalogues cover the Haute-Savoie portion. This is an explicitly local atlas, not automatic nationwide loading on pan. Dates of retrieval and sampling are distinguished. Provider outages are isolated per layer; no fabricated sample data are used.

### River catalogue availability

An HTTP 500 reported on 9 September 2026 came from the Hub’Eau station request; the identical live request subsequently succeeded with 89 local stations. This supports an intermittent provider failure, not a confirmed provider-internal cause. A deterministic HTTP-500-then-success test reproduced the app's immediate failure before the change. The catalogue now retries transient HTTP 500/502/503/504 and network failures up to three total attempts, with 500/1,000 ms backoff and a single 25-second deadline. Abort cancels pending backoff; bad requests, invalid JSON and truncated catalogues are not retried.

`river-catalogue.ts` includes a dated, spatially filtered catalogue in the static page. It is displayed immediately when the river layer is enabled, then refreshed in the browser. Failed refreshes retain the newest successful catalogue, its original retrieval date and the independent AERMC assessments; the sidebar explains the fallback and offers retry. Live analyses may still fail independently, with their existing retry UI. If neither the build nor the browser has a successful catalogue, the explicit error/Retry remains: no station data are invented. The included catalogue refreshes on rebuild, with no new scheduler or client persistent cache. Tests: `scripts/river-availability.test.mjs` and `scripts/check-atlas-river-outage.mjs` (initial outage, dated fallback, independent assessments, failed analyses, recovery and subsequent refresh failure).

Browser verification: 59 inventory markers, 89 river stations and 33 drinking-water commune markers. River station requests project only the fields required by the map to reduce provider latency. Water popups returned actual analyses for Praz-sur-Arly (28 April 2026) and Sallanches station 06820178 (28 February 2013); old sampling dates remain visible rather than implying current measurements. Type checking and production export checks pass.

## Atmo station measurements (replaces the communal index layer)

The atlas now uses Atmo's public [hourly concentration FeatureServer](https://services3.arcgis.com/o7Q3o5SkiSeZD5LK/arcgis/rest/services/Concentrations%20moyennes%20horaires/FeatureServer), linked from [Atmo's official catalogue](https://www.data.gouv.fr/datasets/mes-aura-horaire-no2). Verified layer IDs: PM₂.₅ = 2, PM₁₀ = 4, NO₂ = 1, O₃ = 3. The former WFS/index fallback is no longer used.

- Query each pollutant independently, filtered to the atlas bounds. Follow pagination (2,000 rows/page; at most 10 pages), reject truncation, and bound the whole sequence with a 25-second timeout. Disable requests when the layer is off; abort on unmount or refresh.
- Group by published station code; use published WGS84 coordinates, not commune centres. Preserve hourly start/end timestamps, numeric values, units and raw `statut_valid` codes. The codebook has not been verified: display source codes such as `t`/`f` verbatim, without claiming expert validation.
- Missing values remain missing, never zero. The most recent numerical row has its own timestamp; a newer empty slot is explicitly flagged. Charts break at missing values, missing hours and unit changes; a table exposes all returned observations. Pin colour uses an indicative hourly concentration classification (see below).
- Verified in the browser: PM₂.₅ and O₃ have Passy; PM₁₀ has Bossons; NO₂ has both. These counts reflect this feed and period, not an exhaustive inventory of every operational sensor.
- This feed currently ends on 3 February 2026; it is **historical, not live air quality**. Warn when the newest slot or displayed value is over 48 hours old. Fresh-data access remains a separate provider integration; no credentials are embedded.
- All four pollutants are always displayed when the Atmo layer is enabled, without a selector. Readings are grouped by station code into one pin; its detail overlay contains each available pollutant's values and history. The sidebar lists availability for all four pollutants. Regression tests: `node --experimental-strip-types --test scripts/atmo-stations.test.mjs`. Browser testing covers simultaneous pollutant histories, deduplicated pins and overlay scrolling on desktop and mobile.

### data.gouv.fr versus Geod’air

Verified 9 September 2026: the [data.gouv.fr NO₂ dataset](https://www.data.gouv.fr/datasets/mes-aura-horaire-no2) is an external Atmo catalogue entry, not an independent measurements provider. Its [REST resource](https://www.data.gouv.fr/api/1/datasets/r/da3b9867-a997-42f5-be7a-98e905bd93ec) redirects to the exact hourly FeatureServer layer already queried by `atmo-stations.ts`; using that catalogue therefore does not replace the underlying feed or establish fresher readings. The catalogue also links Atmo CSV/WFS resources, whose actual observation dates and coverage must be verified separately from catalogue modification dates.

## Measurement icons and colours

**Air-only demo presentation:** `DEMO_PIN_PREVIEW` remains enabled for air by request. Air pins use the latest numerical hour irrespective of age (trailing empty slots skipped); unknown air ratings retain the stable illustrative fallback. Set the flag to false to restore freshness-aware air pin colours. This is not a live-quality assessment and should be disabled before production use. **Water layers never use this flag or an illustrative fallback.** Their legend is always visible.

Air uses a wind icon, rivers waves, drinking water a glass, bathing a swimmer. Water uses green → amber → red; unassessed water has a white fill with neutral outline/icon. Textual status and dates are provided in tooltips/detail overlays. This palette and its three-group simplification are atlas design choices, not the providers' official palette. Existing inventory colours are unchanged.

- **Air**: upper bands from the [EEA hourly methodology, revised 2025](https://airindex.eea.europa.eu/AQI/?webgl=0), applied to µg/m³ only. Compare the latest shared time slot, never mixed dates. Worst of the four available pollutants; SO₂ is not connected. No interpolation or modelled gap filling. NO₂ + particles + O₃ required for a positive assessment (NO₂ + particles for traffic stations); partial coverage can still flag a poor measured pollutant, with a warning. Blue for missing/negative/nonfinite values, unsupported units, incomplete coverage or slots older than 6 h. This freshness cutoff is an atlas display policy. Calculations use published concentrations, not a verified official station index; raw validation codes remain visible and are not asserted to be final. Current historical Atmo data consequently remain blue.
- **Drinking water (verified 9 September 2026)**: paginate `communes_udi` in batches of up to 20 communes, size 1,000, max 20 pages; reject incomplete catalogues. Keep only the newest published catalogue year per commune and deduplicate networks/quarters. One latest row per **unique network** supplies repeated sample-level flags from the [official Hub’Eau schema](https://hubeau.eaufrance.fr/api/v1/qualite_eau_potable/api-docs); require the returned sample's network list to contain the requested ID. C = compliant, N = noncompliant, D = derogation, S = no applicable parameter measured. Red for N in either limit flag; amber for derogation or a failed reference; green only when both limit flags and both reference flags are C. Other/incomplete flags remain unassessed. Preserve historical assessed colours with date and a >90-day historical reading cue (NOT a sanitary validity period). The commune navigation pin is red/orange if at least one known network assessment warrants it, with incomplete coverage disclosed; green requires all catalogued networks to be assessed and green. Otherwise outline. The overlay exposes each network, catalogue year, sample date/ID, official conclusion and network-scoped raw analyses. Four concurrent summary calls maximum, shared networks fetched once, cancel on disable/refresh. Verified Passy: five networks in catalogue 2026; four compliant samples and one failed reference at Chatelard, all historical. This is not a current potability verdict.
- **Rivers (verified 9 September 2026)**: build-time POST to the [official AERMC export](https://www.rhone-mediterranee.eaufrance.fr/streams-quality-data/export-data-search), form field `field_sq_departement=531` (Drupal option for Haute-Savoie, not INSEE). [Search/export form](https://www.rhone-mediterranee.eaufrance.fr/surveillance-des-eauxcours-deau/etat-des-cours-deau-evalue-la-station-de-suivi?field_sq_departement=531), [code legend](https://www.rhone-mediterranee.eaufrance.fr/legende-du-fichier-eaux-superficielles). Parse the semicolon CSV, preserving leading-zero IDs, quoted fields, latest published assessment year and unknowns. Match **exact station IDs only** to Hub’Eau; never nearest-neighbour/name matching or raw parameter thresholds. `ECO`: TBE/BE → green, MOY → amber, MED/MAUV → red; unknown/missing → outline. For MEFM/MEA, use `POTENTIEL_ECOLO` and label it ecological *potential*, not status. Original five-class labels are preserved. `CHIM` is a separate textual assessment, with published downgrading parameters. Missing/newer unassessed entries never borrow an older favourable class. Export returned 616 station records with dated assessments; Magland `06061000` publishes 2026 medium ecological potential, good chemical status. Timeout 25 seconds, max 8 MB CSV; source failure yields outlined stations and a sidebar error while raw Hub’Eau analyses remain available. Static production refresh requires rebuilding; the browser refresh button only reloads the station catalogue.

Checks: `node --experimental-strip-types --test scripts/*test.mjs`; water parser, latest-year selection, potential/status separation, network scope, partial coverage, pagination, cancellation and concurrency are covered in `scripts/water-assessments.test.mjs`. Browser fixtures in `scripts/check-atlas-quality.mjs` exercise green, amber, red, historical and outlined water pins, network selection, real server-imported river assessment and desktop/mobile layout. `scripts/check-atlas-popups.mjs` covers shared overlays and all air pollutants.

## ARS API question

### Bathing-water controls

“Eaux de baignade · ARS” retains a registry of six verified sites (only the three CCPMB sites are now fetched/displayed): Passy Îles (`074003360`), Passy Cavettaz (`074003361`), Sallanches Ilettes (`074003362`), Thyez municipale (`074003363`), Morillon municipale (`074003359`) and Samoëns Lac des Dames (`074005813`). The separate EU IDs and site coordinates come from the Ministry's [2026 catalogue](https://www.data.gouv.fr/api/1/datasets/r/e659289d-fdc2-46c2-a025-d7e1264e4197), under the [official open-data dataset](https://www.data.gouv.fr/datasets/donnees-de-rapportage-de-la-saison-balneaire-1) (Licence Ouverte). Portal IDs were cross-checked against the [Ministry map service](https://sigmas.social.gouv.fr/server/rest/services/baignades/fra_vue_baignade/MapServer/5). Coordinates locate bathing sites, not each individual sample; the two Passy records must not be merged. This is a curated local registry, not an automatically expanding catalogue. All six sites returned five samples in each of 2025 and 2026 when checked on 8 September 2026.

`bathing-water-source.ts` imports the current and previous calendar seasons from the Ministry's `consultSite.do?annee=…&dptddass=074&isite=…&plv=all&site=…` HTML, server-side (no browser CORS proxy or invented API). Three concurrent requests maximum; 15-second timeout per page and 25-second overall deadline; failures isolated by site and season. Its narrow parser validates site identity, season/date, units and column counts, retaining missing values and `<15` strings; the two threshold columns are excluded. Changed/unavailable pages yield an explicit error and source link, not invented measurements. Only the two mandatory bacterial parameters and the source's sample assessment are imported, not chemical screening, bathing bans or annual classifications. Pins use the latest sample's Bon/Moyen/Mauvais assessment → green/amber/red; unknown uses an outlined pin, never a demo fallback. Dates and scope stay explicit in the large overlay.

The static export contains the retrieved results: production updates require a rebuild, not the atlas's browser-only external refresh button. Development uses Next's one-hour fetch cache; retrieval dates are render/import dates (a response may come from that cache). No new scheduler is installed. The site registry/coordinate catalogue is versioned separately and should be checked when the Ministry publishes a new catalogue. Tests: `node --experimental-strip-types --test scripts/bathing-water.test.mjs`; `scripts/check-atlas-bathing.mjs` verifies real 2025/2026 data, marker toggles and desktop/mobile overlays.

No documented general API for the ARS regional website was identified. Use the national public dataset appropriate to the subject. Drinking-water results are already available through Hub’Eau, avoiding duplicate ARS/Hub’Eau layers representing the same source. [AtlaSanté lists some AuRA drinking-water catchment/protection maps as restricted](https://www.atlasante.fr/accueil/cartes-et-outils/nos-cartes-a-acces-restreint); do not assume every ARS map is public or reusable.

## Recommended subsequent layers (not yet implemented)

1. **Géorisques industrial installations, CASIAS, soil-pollution records/SIS**: complementary context for the citizen inventory. [Industrial dataset](https://www.georisques.gouv.fr/donnees/bases-de-donnees/installations-industrielles), [soil-pollution dossier](https://www.georisques.gouv.fr/consulter-les-dossiers-thematiques/dossier-expert-sur-les-sites-et-sols-potentiellement-pollues). CASIAS records historical activities, not confirmed contamination; keep categories distinct and preserve source identifiers for overlaps.
2. **Hub’Eau hydrometry and groundwater levels**: contextualize transport in the Arve and water-resource variation, with timestamped observations.
3. **IGN aerial imagery / terrain and administrative boundaries**: useful base-map/context choices. Check each Géoplateforme layer's access and attribution; not all IGN products are unrestricted.
4. **Air/noise co-exposure**: Atmo's public ArcGIS directory exposes commune/EPCI datasets for this subject; verify indicator definition, period, licensing and coverage before connecting.

For every new layer, document spatial support, temporal resolution, units, licence, attribution, limits/pagination, CORS, error state and potential overlap. Add the definition and loader in `src/lib/environmental-layers.ts` and its rendering/control in `src/components/AtlasMap.tsx`.

## Annual road traffic source

**Scope correction, 10 September 2026:** road geometry is now restricted to the union of the **ten CCPMB communes**, not the broad atlas query rectangle: Combloux, Les Contamines-Montjoie, Cordon, Demi-Quartier, Domancy, Megève, Passy, Praz-sur-Arly, Saint-Gervais-les-Bains and Sallanches. Servoz is excluded. The published [official commune contours](https://geo.api.gouv.fr/epcis/200034882/communes?fields=nom,code,contour&format=geojson&geometry=contour) are pinned with retrieval date/source in `src/lib/data/ccpmb-boundaries.json`. `ccpmb-territory.ts` intersects road segments with their polygon union, preserving holes and disconnected pieces; the broad rectangle is only a provider query envelope. All atlas data layers now use this same perimeter. The selection now includes D339 and N205 alongside the original seven roads. Live verification: **27 retained sections, 20 with 2024 counts and seven without**, with every retained segment midpoint inside the territory. The two added roads are **D339 (10,530 vehicles/day)** and **N205 (18,628 vehicles/day on its counted section)**. N205 also has one unmeasured section, retained as dashed geometry; all sections remain clipped to the commune boundaries. The broader coverage counts below describe the earlier rectangular query, not the current display. Tests cover the exact commune registry, exclusion of Servoz/Chamonix, boundary crossings, shared edges, holes and disconnected paths.

Verified 9 September 2026: the [DDT74 road-traffic dataset](https://www.data.gouv.fr/datasets/trafic-routier-en-haute-savoie) is published under Licence Ouverte 2.0. Its BD CARTO-derived road geometries carry annual average daily traffic (TMJA, vehicles/day), not live congestion, speed or pollution measurements. Although the catalogue was updated in July 2026 and a separate 2025 PDF exists, the verified WFS schema ends at **2024**; do not relabel these readings as 2025.

The [public WFS capabilities](https://ogc.geo-ide.developpement-durable.gouv.fr/wxs?map=/opt/data/stack/mapfiles/1.4/org_38090/7bc62133-b9b6-407a-b937-a75b120540ef.internet.map&SERVICE=WFS&REQUEST=GetCapabilities) expose `ms:L_RESEAU_TRAFIC_ROUTIER_L_074`. Request WFS `1.1.0`, `GetFeature`, `SRSNAME=EPSG:4326`, and `BBOX=45.7,6.45,46.1,7.1,urn:ogc:def:crs:EPSG::4326`. The returned GML has `MultiCurve` / `curveMember` / `LineString` / `posList` geometry in **latitude, longitude order**; reverse each pair for GeoJSON. GeoJSON output is explicitly unsupported, and WFS 1.0 ignored the requested output CRS during verification. Attributes are `N_ROUTE`, `T_COMPT`, `N_COMPT`, `ID`, `TMJA_24`, `TMJA_PL_24` and `PCT_PL_24`, plus historical annual fields. Some station IDs are blank; they are not universally unique geometry identifiers.

The raw atlas-bounds response contains 79 features, of which 39 match A40, D1205, D909, D1212, D13, D39 and D902 exactly. All seven roads have 2024 counts: 31 matching features are assessed and eight have no 2024 count (four unmeasured sections and four discontinued counting sites with older readings). Zero placeholders are **not observed zero traffic**; keep these sections unassessed rather than borrowing an adjacent road's count or silently promoting an old count. Bounding-box intersection includes complete source features, so any rendering clip is a separate operation. Import this dated source at build time; production refresh requires a static rebuild, not browser polling or a newly implied live feed.

Coverage follow-up, verified 10 September 2026 against the same [DDT74 WFS](https://ogc.geo-ide.developpement-durable.gouv.fr/wxs?map=/opt/data/stack/mapfiles/1.4/org_38090/7bc62133-b9b6-407a-b937-a75b120540ef.internet.map&SERVICE=WFS&VERSION=1.1.0&REQUEST=GetFeature&TYPENAME=ms:L_RESEAU_TRAFIC_ROUTIER_L_074&SRSNAME=EPSG:4326&BBOX=45.7,6.45,46.1,7.1,urn:ogc:def:crs:EPSG::4326&MAXFEATURES=1000) and clipped to the atlas rectangle: **12 additional route identifiers have positive 2024 counts across 23 sections**: D4, D6, D19, D26, D106, D306, D339, D907, D1506, N205, `rampeTMB` and `TMB`. D186 and D2026 also appear, but have no usable 2024 count. These are historical source-availability findings for the wider rectangle; the current selection is the original seven roads plus D339 and N205, clipped to the CCPMB boundary. Counts describe individual sections, not a uniform value for an entire road; the [official catalogue](https://www.data.gouv.fr/datasets/trafic-routier-en-haute-savoie) covers selected structural roads and counted non-structural sections, not an exhaustive inventory of every road or every possible traffic-count source.

Implementation: `road-traffic-source.ts` imports the bounded WFS response (25 seconds, maximum 4 MB, rejects a 1,000-feature limit hit, changed CRS/geometry and truncated payloads). `road-traffic.ts` clips real line segments to the atlas rectangle without connecting disconnected pieces. Geometry-derived IDs supplement missing/nonunique published IDs. The latest completed annual column is used consistently across all sections; absent counts never borrow previous years. `RoadTrafficLayer` supplies the opt-in layer, opacity, five fixed volume classes (<2,500; <5,000; <10,000; <20,000; ≥20,000 vehicles/day), dashed unknown sections and keyboard-accessible SVG lines opening the shared details overlay. These classes are display choices, not congestion or health thresholds. Provider failure leaves an explicit source error, not fictitious counts. Unit tests: `scripts/road-traffic.test.mjs`; real-data desktop/mobile browser checks: `scripts/check-atlas-traffic.mjs`.
