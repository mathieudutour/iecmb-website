# Atlas environnemental

Page: `/atlas`. The existing `/carte` remains the inventory interface and does not advertise the atlas yet. Layer controls, opacity, attribution, dates, retry and recentering are available. Browser-side external requests run only for enabled layers; bathing-water results, the river station catalogue and river assessments are fetched at build/render time alongside the inventory. Detailed Hub’Eau analyses run on clicking a water point/network; drinking-water summaries load on layer activation (one row per unique distribution network, four requests concurrently at most). All requests are bounded and cancellable.

## Current atlas perimeter (10 September 2026)

Every data layer is restricted to the polygon union of the ten CCPMB communes using `ccpmb-territory.ts` and the pinned official commune contours: inventory, Atmo (hourly/daily and seeded stations), rivers (build snapshot and browser refresh), drinking-water commune markers, bathing sites, biosurveillance demos, soil demos, roads and residential heating. Point filtering precedes displayed counts and downstream detail requests. The heatmap uses per-row polygon intersections, including holes and shared borders, to make all out-of-territory pixels transparent. Initial view and recentering use the territory bounds; the background map remains available as geographic context.

The inventory filter is an immutable atlas-only view (`atlas-inventory.ts`); `/carte` and its shared source are unchanged. The six-site bathing registry is preserved, but only Passy Îles, Passy Cavettaz and Sallanches Ilettes are fetched and shown. Servoz, Thyez, Morillon, Samoëns and the Chamonix valley are outside the atlas data scope. Unmapped inventory records remain accessible in the separate inventory, not assigned invented map locations.

Verified export: 59 inventory sites and 29 river stations; live commune catalogue: exactly the ten CCPMB communes. Roads retain 27 sections (20 counted); bathing retains three sites. Browser regression `scripts/check-atlas-territory.mjs` checks desktop/mobile export points, cached river outage/recovery, outside-point rejection for live water/air, sidebar counts, demo layers and heatmap pixels. Unit coverage includes source immutability, scanline holes/unions and every coloured pixel of a test raster. Production build, 62 tests, desktop/mobile territory, road and bathing checks pass. Earlier verification counts below refer to the previous broader perimeter.

### River catalogue availability

An HTTP 500 reported on 9 September 2026 came from the Hub’Eau station request; the identical live request subsequently succeeded with 89 local stations. This supports an intermittent provider failure, not a confirmed provider-internal cause. A deterministic HTTP-500-then-success test reproduced the app's immediate failure before the change. The catalogue now retries transient HTTP 500/502/503/504 and network failures up to three total attempts, with 500/1,000 ms backoff and a single 25-second deadline. Abort cancels pending backoff; bad requests, invalid JSON and truncated catalogues are not retried.

`river-catalogue.ts` includes a dated, spatially filtered catalogue in the static page. It is displayed immediately when the river layer is enabled, then refreshed in the browser. Failed refreshes retain the newest successful catalogue, its original retrieval date and the independent AERMC assessments; the sidebar explains the fallback and offers retry. Live analyses may still fail independently, with their existing retry UI. If neither the build nor the browser has a successful catalogue, the explicit error/Retry remains: no station data are invented. The included catalogue refreshes on rebuild, with no new scheduler or client persistent cache. Tests: `scripts/river-availability.test.mjs` and `scripts/check-atlas-river-outage.mjs` (initial outage, dated fallback, independent assessments, failed analyses, recovery and subsequent refresh failure).

Browser verification: 59 inventory markers, 89 river stations and 33 drinking-water commune markers. River station requests project only the fields required by the map to reduce provider latency. Water popups returned actual analyses for Praz-sur-Arly (28 April 2026) and Sallanches station 06820178 (28 February 2013); old sampling dates remain visible rather than implying current measurements. Type checking and production export checks pass.

## Atmo station measurements (replaces the communal index layer)

The atlas now uses Atmo's public [hourly concentration FeatureServer](https://services3.arcgis.com/o7Q3o5SkiSeZD5LK/arcgis/rest/services/Concentrations%20moyennes%20horaires/FeatureServer), linked from [Atmo's official catalogue](https://www.data.gouv.fr/datasets/mes-aura-horaire-no2). Verified layer IDs: PM₂.₅ = 2, PM₁₀ = 4, NO₂ = 1, O₃ = 3. The former WFS/index fallback is no longer used.

- Query each pollutant independently, filtered to the atlas bounds. Follow pagination (2,000 rows/page; at most 10 pages), reject truncation, and bound the whole sequence with a 25-second timeout. Disable requests when the layer is off; abort on unmount or refresh.
- Group by published station code; use published WGS84 coordinates, not commune centres. Preserve hourly start/end timestamps, numeric values, units and raw `statut_valid` codes. The codebook has not been verified: display source codes such as `t`/`f` verbatim, without claiming expert validation.
- Missing values remain missing, never zero. The most recent numerical row has its own timestamp; a newer empty slot is explicitly flagged. Charts break at missing values, missing hours and unit changes; a table exposes all returned observations. Pin colour uses an indicative hourly concentration classification (see below).
- Verified in the browser: PM₂.₅ and O₃ have Passy; PM₁₀ has Bossons; NO₂ has both. These counts reflect this feed and period, not an exhaustive inventory of every operational sensor.
- This feed currently ends on 3 February 2026; it is **historical, not live air quality**. Warn when the newest slot or displayed value is over 48 hours old. Fresh-data access remains a separate provider integration; no credentials are embedded.
- All four pollutants are always displayed when the Atmo layer is enabled, without a selector. Readings are grouped by station code into one pin; its detail overlay contains each available pollutant's values and history. The sidebar lists availability for all four pollutants. Regression tests: `node --experimental-strip-types --test scripts/atmo-stations.test.mjs`. Browser testing covers simultaneous pollutant histories, deduplicated pins and overlay scrolling on desktop and mobile.

Calculations use published concentrations, not a verified official station index; raw validation codes remain visible and are not asserted to be final. Current historical Atmo data consequently remain blue.

Development uses Next's one-hour fetch cache; retrieval dates are render/import dates (a response may come from that cache). No new scheduler is installed. Tests: `node --experimental-strip-types --test scripts/bathing-water.test.mjs`; `scripts/check-atlas-bathing.mjs` verifies real 2025/2026 data, marker toggles and desktop/mobile overlays.

### Industrial installations and soil records: immediately viable

The [official v1 OpenAPI schema](https://www.georisques.gouv.fr/api/v3/api-docs/georisques-api-v1) documents `installations_classees`, `ssp/casias`, `ssp/instructions` (administrative information on suspected or established pollution, formerly BASOL), and `ssp/conclusions_sis`. These accept `code_insee` with up to ten comma-separated commune codes, plus one-based `page` and `page_size`. The [authentication guidance](https://www.georisques.gouv.fr/inscription) explicitly keeps v1 accessible without a token; v2 needs an annual token obtained through Cerbère or FranceConnect. Prefer v1 for a credential-free first integration. If v2 is adopted, keep its token server-side, outside the static bundle.

Live, unauthenticated checks using only Passy `74208` and Sallanches `74256` returned HTTP 200:

Real coordinates, establishment identifier `codeAIOT`, operating status, regulatory regime and dated inspection/document links are available. An ICPE classification is not an observation of pollution; keep it separate from citizen reports and from measured emissions.
- [CASIAS](https://www.georisques.gouv.fr/api/v1/ssp/casias?code_insee=74208,74256&page_size=100): API reports 208 records across three pages; only the first 100 were fetched in this research pass. Example: DLI, Sallanches, point geometry and source fiche. This verifies local records, not a complete local catalogue. - [Administrative soil-pollution records](https://www.georisques.gouv.fr/api/v1/ssp/instructions?code_insee=74208,74256&page_size=100): six records, one complete page. Preserve the regulatory/source classification and historical dates; do not relabel an old record as a fresh measurement. ### IREP inventory enrichment — source verified 10 September 2026

The [download widget's public catalogue](https://www.georisques.gouv.fr/webappReport/ws/telechargement/irep?anneemin=2003) currently lists **2024** as its latest non-null annual archive; 2025 and 2026 are null. This is more precise than the landing page's stale December 2024 metadata. The verified [2024 official ZIP](https://files.georisques.fr/irep/2024.zip) is 7,578,969 bytes, with eight CSV members totaling 126,467,453 uncompressed bytes (member timestamps 2025-11-13). Read only `2024/etablissements.csv` (3,568,492 bytes) and `2024/emissions.csv` (9,696,425 bytes) for this feature; waste production/treatment and water volumes are different datasets and must not be conflated with pollutant releases. Import at build time, preserving the reporting year and retrieval date; this is not a live measurements API. A research copy is at `/tmp/iec-irep-2024.zip`.

Both files are UTF-8, semicolon-separated, with CRLF records. The establishment schema is `identifiant;nom_etablissement;numero_siret;adresse;code_postal;code_insee;commune;code_departement;departement;code_region;region;coordonnees_x;coordonnees_y;code_epsg;code_ape;libelle_ape;code_eprtr;libelle_eprtr`. The emissions schema is `identifiant;nom_etablissement;code_postal;code_insee;commune;code_departement;departement;code_region;region;annee_emission;milieu;polluant;quantite;unite`. Join on the exact string `identifiant`, retaining leading zeroes. Coordinates for the local records use EPSG:4326, x longitude / y latitude. `quantite` is not a numeric-only column: preserve `< seuil` and original units, rather than coercing unavailable quantities to zero.

The [official interpretation guidance](https://www.georisques.gouv.fr/consulter-les-dossiers-thematiques/registre-des-emissions-polluantes) warns that published `0` values can mean an actual null quantity, below-threshold reporting, or inaccurate/unavailable information; SGL has two such rows. Preserve them as **published zero, interpretation unspecified**, not verified absence of emissions. `< seuil` concerns declaration thresholds, not ambient health limits. Published annual quantities may come from measurements, calculations or estimates; these CSVs do not provide a row-level determination method. Missing pollutants/years do not imply no releases, coverage is not exhaustive, and declarations cannot independently establish health risk. Keep media distinctions such as `Eau (direct)` intact. No browser CORS dependency is necessary for a build-time import. The [official legal notice](https://www.georisques.gouv.fr/mentions-legales) applies Licence Ouverte to downloadable datasets; the catalogue footer specifies Etalab 2.0 unless otherwise stated. Attribute Géorisques / INERIS, retaining the official archive URL, year and retrieval date.

Provider failure returns an explicit IREP status without preventing inventory loading or inventing data. The exported site refreshes only on a new build, not by browser polling.

Verified 9 September 2026: the [DDT74 road-traffic dataset](https://www.data.gouv.fr/datasets/trafic-routier-en-haute-savoie) is published under Licence Ouverte 2.0. Its BD CARTO-derived road geometries carry annual average daily traffic (TMJA, vehicles/day), not live congestion, speed or pollution measurements. Although the catalogue was updated in July 2026 and a separate 2025 PDF exists, the verified WFS schema ends at **2024**; do not relabel these readings as 2025.

The [public WFS capabilities](https://ogc.geo-ide.developpement-durable.gouv.fr/wxs?map=/opt/data/stack/mapfiles/1.4/org_38090/7bc62133-b9b6-407a-b937-a75b120540ef.internet.map&SERVICE=WFS&REQUEST=GetCapabilities) expose `ms:L_RESEAU_TRAFIC_ROUTIER_L_074`. Request WFS `1.1.0`, `GetFeature`, `SRSNAME=EPSG:4326`, and `BBOX=45.7,6.45,46.1,7.1,urn:ogc:def:crs:EPSG::4326`. The returned GML has `MultiCurve` / `curveMember` / `LineString` / `posList` geometry in **latitude, longitude order**; reverse each pair for GeoJSON. GeoJSON output is explicitly unsupported, and WFS 1.0 ignored the requested output CRS during verification. Attributes are `N_ROUTE`, `T_COMPT`, `N_COMPT`, `ID`, `TMJA_24`, `TMJA_PL_24` and `PCT_PL_24`, plus historical annual fields. Some station IDs are blank; they are not universally unique geometry identifiers.

The raw atlas-bounds response contains 79 features, of which 39 match A40, D1205, D909, D1212, D13, D39 and D902 exactly. All seven roads have 2024 counts: 31 matching features are assessed and eight have no 2024 count (four unmeasured sections and four discontinued counting sites with older readings). Zero placeholders are **not observed zero traffic**; keep these sections unassessed rather than borrowing an adjacent road's count or silently promoting an old count. Bounding-box intersection includes complete source features, so any rendering clip is a separate operation. Import this dated source at build time; production refresh requires a static rebuild, not browser polling or a newly implied live feed.

Coverage follow-up, verified 10 September 2026 against the same [DDT74 WFS](https://ogc.geo-ide.developpement-durable.gouv.fr/wxs?map=/opt/data/stack/mapfiles/1.4/org_38090/7bc62133-b9b6-407a-b937-a75b120540ef.internet.map&SERVICE=WFS&VERSION=1.1.0&REQUEST=GetFeature&TYPENAME=ms:L_RESEAU_TRAFIC_ROUTIER_L_074&SRSNAME=EPSG:4326&BBOX=45.7,6.45,46.1,7.1,urn:ogc:def:crs:EPSG::4326&MAXFEATURES=1000) and clipped to the atlas rectangle: **12 additional route identifiers have positive 2024 counts across 23 sections**: D4, D6, D19, D26, D106, D306, D339, D907, D1506, N205, `rampeTMB` and `TMB`.
